# Science Task Pipeline（TB-Science）

> 开源版：一条“人类说口令、Agent 照 Skill 做、结果记台账”的科学任务生产流水线。上手见 [MANUAL.md](MANUAL.md)；许可与第三方材料说明见 [LICENSE](LICENSE) 和 [NOTICE.md](NOTICE.md)。

TB-Science 科学任务的生产流水线仓库。仓库里放三样东西：一份[要求书](specs/tb-science-requirements.md)、固定 Skill、两个台账。人类只说口令，Agent 照 Skill 做，结果记进台账。

**看结果只需打开一页**：[结果看板](flows/tb-science/board.md)（出了多少题、在跑几道、过了几道、每题来源与结果）。

## 人类怎么用

| 想做什么 | 对谁说 | 口令 | 得到什么 |
| --- | --- | --- | --- |
| 让 GPT Pro 提供选题素材 | 任意加载了本仓库的 Agent | `启动选题` | 一份提示词文件 → 你复制给 GPT Pro，把回复贴回 `materials/<素材号>.md`，再说 `登记素材 <素材号>`。回复只是素材，成不成题由 `研究出题` 判断。提示词固定带[目标难度带与弱模型画像](flows/tb-science/calibration-models.md) |
| 把外部题目放进素材库 | 任意 Agent | `登记素材`（附上文件或压缩包，不带素材号） | Agent 自己编号：原文与元数据进 `src-NNN`，入库条目拆成若干 `mat-NNN` 候选；门槛只挡占位、空条目和重复，见 [tb-topic 外部素材入库](skills/tb-topic/SKILL.md#外部素材入库)。回报每批入库多少 |
| 多开一台执行机 | 任意 Agent | `构建执行单元 <机器名>` | 一段启动 prompt → 贴进新 Codex 对话（弱模型 key 可不填，2026-10-29 起不跑弱模型）；它自己装 Docker/Harbor、过两条验收、在 [registry](flows/tb-science/boot/registry.md) 登记后回“就绪” |
| 让执行机自己领题做 | Codex 执行单元 | `持续执行` | 它从队列顶部领题，做完登记就领下一题，领不到才停。等运行时用一条阻塞命令等到结束，不反复查看、不报“还在跑”（tb-run“省力协议”）。**达标题自动审查**：另起独立进程审，材料类退回自己修，最多 3 轮；通过就把 zip 归档到执行机 `deliveries/`，回报“审查通过”；3 轮仍不过、或缺的是轨迹深度或通过数（校准类），才回报退回。最长成功轨迹 50–59 步、其余条件都满足的题算**近达标**：同样冻结、审查、归档到 `deliveries/near60/`、登记，不再改难；包名带 `-d50`，看板单独计数，和 ≥ 60 的达标题不混。中途不问人类：遇到障碍自己推进，同一障碍连续 ≥ 6 小时或 ≥ 10 种办法都不行才标 `阻塞` 回报（题目不可用 / 本机故障），由你判断。**同机多开**：再开一个 Codex 对话，贴同一份启动 prompt，说 `持续执行`，其余不用改；每题 [台账 1](flows/tb-science/ledger/tasks.md) 多一行、[runs/](flows/tb-science/runs/README.md) 多一个目录；手动补审退回的题自动回队列顶部，由同机修 |
| 指定做某一题 | Codex 执行单元 | `执行题目 <题号>` | 同上，只做这一题 |
| 补审（平时不用说） | 执行机上另开的 Codex 对话 | `审查` | 审完本机所有**达标**未审的题，用于自动审查没起来或存量的题；每题 [台账 2](flows/tb-science/ledger/reviews.md) 多一行；退回的题回队列顶部；不达标题不审查 |
| 把素材加工成题 / 自主研究出题 | 云端 Claude 会话或定时任务 | `研究出题` | 一轮至少推进 3 件：先给队列顶部 ≤ 3 道旧题回补“首发解”检验（挂了就升对抗档，过了就退回出题），再把待加工素材全部加工（每个可成题的候选各成一题，不能成题的否决），不足 5 件才自主研究；待执行满 50 停；[队列](flows/tb-science/topics/queue.md)重排。定时任务 prompt 见 [boot/cloud-research.md](flows/tb-science/boot/cloud-research.md)。2026-10-29 起按[对抗出题规范](flows/tb-science/adversarial-design.md)出题：每题先做对抗设计（零点名 + 延迟暴露 / 证据分叉等手法），草稿只实跑参考解 1 分、首发解 0 分、3 种子贴边容差，题头部带 `对抗清单`，排队在没有清单的题之上 |
| 执行机空着、想多试题 | 任意出题侧 Claude 会话（可同时开多个） | `快速出题` | 和 `研究出题` 一样从素材库取候选、产出题目进队列，但**不写草稿、不实跑、不探针**，靠出题模型的领域知识把设计和构建简报写清楚，一轮至少 5 道；执行机按简报从零构建。同样按对抗出题规范做对抗设计，首发解写成算法由执行机实跑作闸门（通过就退回出题，不跑模型）。对抗档内排在研究出题的题之后，专门填满空闲执行机。看板“来源链路”“出题流程”两表对比达标率 |
| 把跑过的题改难再发 | 出题侧 Claude 会话（云端或本地，可同时开多个） | `复审改难` | [打分表](flows/tb-science/runs/scores.md)多行与[对手档案](flows/tb-science/adversarial-design.md#f-对手档案只追加)多行（GPT 5.6 实际怎么做的、哪种手法有效）；强模型跑过但没落进难度带的题**每轮全部**修成新题排到队列顶部：有加难旋钮的直接拧旋钮 + 零点名修复（≤ 30 分钟），没有的全套对抗设计。多开时各对话用 [claims/](flows/tb-science/claims/README.md) 自动错开，不会重复打分或改同一道题 |
| 出题时用弱模型探一探（有 key 自动） | 本机有 DeepSeek key 和 Docker 的出题会话 | 不用说；给已在排的题补探针说 `预筛 <题号>` | 有 key 的 `研究出题` / `复审改难` 开局会说“本轮出题使用本机 DeepSeek key”，写题时让弱模型快速探题（一次性作答约 1.5–3 分钟：DS 写一份脚本跑一次、最多修两次），结果只作排序参考（一次就做对的排后，不改设计、不拦题），题头部记 `预筛` 行。不是校准证据；云端没 key 照旧。key 只放本机 `.env`（已忽略，不进仓库） |
| 让所有对话用上最新规则 | 不用说；想立刻生效时对任一对话说 | `同步规则` | 各 Agent 在会话开始、每轮领题前、判定和登记前、每次提交前自动拉取并比对规则，有变化就照新规则继续，回报里多一行 `规则已更新到 …`。每题登记回报带 `规则版本`，与[看板](flows/tb-science/board.md)总览的“规则最新版本”一致即已跟上 |
| 重新生成看板 | 任意 Agent | `刷新看板` | [看板](flows/tb-science/board.md)更新（其他口令完成时会自动刷） |

两个台账是唯一事实，直接在 GitHub 页面看：[台账 1 已完成题目](flows/tb-science/ledger/tasks.md) · [台账 2 审查结果](flows/tb-science/ledger/reviews.md) · [运行摘要](flows/tb-science/runs)。Agent 回报文件时也会直接给 GitHub 链接。
