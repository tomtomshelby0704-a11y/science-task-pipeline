# tb-quick：快速出题

## 触发口令

- `快速出题`：由出题侧 Claude（云端或本地，手动会话或定时任务）跑**一轮**，可以同时开多个对话。不需要弱模型 key，也不需要 Docker。

## 目的

[研究出题](../tb-research/SKILL.md)是质量路线：每题写可运行草稿、多种子实跑、有 key 时再探针，一题要几十分钟到几小时，执行机常常因此空着。本 Skill 是**并行的第二条出题链路**：

- 输入输出和研究出题一样，都是从 [materials/](../../flows/tb-science/materials/README.md) 取候选，产出 `topics/<题号>.md` 进队列。
- 区别只有一个：**快**。不写草稿、不实跑、不探针，靠出题模型的科学判断和领域知识把设计写清楚，由执行机按构建简报从零构建题包（tb-run 本来就支持没有草稿的题）。

判据和研究出题完全相同，红线、近亲、难度落点、否决纪律都不放宽；省掉的只是“在出题侧把题跑通”这一步。2026-10-29 起两条链路同样都是**对抗式**的（[对抗出题规范](../../flows/tb-science/adversarial-design.md)）：快速出题不实跑首发解，但要把首发解写成算法并写明它预计挂在哪，由执行机 tb-run 第 3 步实跑作闸门（首发解通过就退回出题，不跑模型）。两条链路哪条达标率高，看看板“按来源”与“对抗 vs 非对抗”统计。

## 输入

| 文件 | 用途 |
| --- | --- |
| `flows/tb-science/materials/*.md` | 待加工素材（状态 `待加工` 或 `待加工（复审）`） |
| [claims/](../../flows/tb-science/claims/README.md) | 素材锁 `research-<素材号>.md`，与研究出题**共用**，两条链路自动互斥 |
| [要求书 第一阶段](../../specs/tb-science-requirements.md#第一阶段-立项与设计)、[5.1](../../specs/tb-science-requirements.md#51-多样性与分组) | 选题红线、近亲 |
| [adversarial-design.md](../../flows/tb-science/adversarial-design.md) | 对抗出题规范：对手画像、六种手法、首发解、对抗清单与旋钮、对手档案（难度落点必须引用） |
| [calibration-models.md](../../flows/tb-science/calibration-models.md)、[runs/scores.md](../../flows/tb-science/runs/scores.md) | 难度带、弱模型画像、实证修正；同类设计的实测结论 |
| `flows/tb-science/topics/*.md`、`runs/` | 去重、近亲；执行记录里的 `简报偏离` / `简报缺口` |
| [topic.md 模板](../tb-topic/templates/topic.md) | 题文件格式 |

## 输出

- `flows/tb-science/topics/<题号>.md`：每个可成题候选一道，12 个字段与 `## 构建简报` 七小节齐全。头部：
  - `- **状态**：待执行`、`- **起始候选**：1`
  - `- **来源对话**：快速出题（素材 <素材号> 候选 <N>，<会话标识>），<日期>`
  - `- **对抗清单**：v1，<日期>；手法 <编号>；首发解 未实跑（执行机闸门）；零点名 自查；分叉 <m 处>；旋钮 <k 个>`
  - `- **草稿**：无（快速出题：未实跑，执行机按构建简报从零构建）`
- `flows/tb-science/materials/<素材号>.md`：状态与每个候选的裁决，写法同研究出题。
- `queue.md` 重排、`board.md` 刷新；全部推到 `main`。
- **不产出** `drafts/`，不做探针，不做自主研究。

## 步骤

本 Skill 不跑脚本；单轮 ≤ 3 小时，到点把已完成的推上去、释放占用，停止原因写 `时间预算到`（[AGENTS.md 出题侧算力与时间预算](../../AGENTS.md#出题侧算力与时间预算)）。

1. `git pull --rebase origin main`，数 `topics/*.md` 中状态 `待执行` 的题得 N。N ≥ 50 → 跳到第 5 步。
2. **占素材**：按 [claims/README](../../flows/tb-science/claims/README.md) 占 `claims/research-<素材号>.md`，与研究出题同一把锁。从**编号最大**的待加工素材取起（研究出题从最小取起）；已有未过期占用、素材头部有 2 小时内的 `加工中` 标记、或 push 撞上 → 换下一份。都占不到或没有待加工素材 → 第 5 步。
3. **逐候选判断**：判据一律按 [tb-research 第 2 步](../tb-research/SKILL.md#步骤)：红线、近亲、难度落点、否决纪律、复审素材的写法，不另立标准。能成题的，用领域知识改写成题，每个候选控制在 **20 分钟**以内（多出的 5 分钟全给对抗设计）：
   - **对抗设计**（先于一切，规范 C–E 节）：选 ≥ 2 种手法——必含手法 1（零点名），且含手法 2（延迟暴露）或 3（证据分叉）之一。写首发解算法（≤ 10 行：GPT 5.6 看完题面第一反应会怎么写）并写明"预计在第几层、哪个子检查、哪个量上偏多少"；用了手法 2 的写分层表，用了手法 3 的写分叉决策表（各分支在生成规格里都要真实出现、写出占比）；≥ 2 个加难旋钮给具体数值。设计不出"首发解必挂的那一层"就不成题。
   - **设计**：优先用对手档案（规范 F 节）已判 `有效` 的手法组合与 calibration-models 第 4 节的实证结论。复杂因素只能从数据诊断得出，不能照题面清单实现；多环节耦合，前一环的偏差会传到后一环、超出容差。难度落点写清"本题用手法 <编号>，对手档案 #<编号>；预计 GPT 5.6 四次成功 1–2 次、至少一条成功轨迹 ≥ 60 步、GPT 5.6 会败在哪一环"的理由——不许只写"预计败在 X 环"而不说用了哪种手法。
   - **泄漏自查**（规范手法 1，必做）：题面要点、README 要点、文件名、表头、协议文本里不得出现陷阱的存在、处理方法或提示词；点出了就改材料。
   - **数据**：优先写自己合成的生成器规格（numpy / scipy 可离线），真值随生成器产出，省掉外部数据的许可核实。
   - **核实**：不做广泛检索。只有用到具体外部工具或数据集时，查一次它的来源、版本和许可；查不到就在简报第 7 小节写“未核实，worker 构建时确认”。相似性自查写明对照了本仓库哪些题和你所知的哪些公开评测。
   - **构建简报**七小节齐全，按 worker 能直接动手的粒度写：第 2 小节写生成规格与真值核对方法，第 3 小节写验证器子检查与容差的**推导思路**（按规范手法 5：参考解离散度 1.5–2 倍与"首发解仍挂"取小，执行机冻结时只放宽不收紧），第 6 小节第一项写首发解（算法 + 预计挂在哪），再写合理简化及其为什么会失败，第 7 小节含 ≥ 2 个旋钮。第 2、3 小节标注“未实跑，worker 实测后冻结”。先读 `topics/*.md` 执行记录里反复出现的 `简报缺口`，在新简报里写到。
   - 近亲自查同 tb-research 第 4 步。
4. **写题**：按 tb-topic 的占号规则写 `topics/<题号>.md`，push 被拒就重算题号；素材头部的候选裁决与题文件同一 commit，同时更新锁的心跳。素材全部候选处理完：状态改 `已加工（→ …）` / `已否决（…）`，同一 commit 删掉锁。回到第 2 步取下一份。一轮在 **成题 ≥ 5 道**、或素材清零、或 N ≥ 50 时停。
5. **排序与看板**：按 [tb-research 第 6、7 步](../tb-research/SKILL.md#步骤)重排 queue.md、刷新看板（快速题在其分档里的位置见那里），同一 commit push。
6. 回报两行：`本轮快速出题 K 道：<题号（手法 …）列表>；否决 <素材号 候选 N：原因，…>；停止原因 <成题 ≥ 5 / 素材清零 / 达上限 50 / 时间预算到>`，附各新题 `blob` 链接；第二行 queue.md 与 board.md 的 `blob` 链接。

**退回出题的题**：队列外状态为 `退回出题（首发解通过，…）` 的题（执行机闸门或研究出题回补退回的），本 Skill 也可领来重写：`git pull --rebase` 后把状态改为 `改写中（<会话标识>）` 并 push 占住，按第 3 步重新做对抗设计（原号、原文件、原地改，保留"退回出题"行作历史），对抗清单写 `v2`，状态回 `待执行`。一道算 K +1。

## 完成判据

- 本轮碰过的素材都已 `已加工` 或 `已否决`，每个候选有裁决；占过的锁都已删除。
- 每道新题 12 个字段齐全（“难度落点”写明手法编号并引用对手档案），构建简报七小节齐全（第 6 小节首项为首发解算法与预计失败处，第 7 小节 ≥ 2 个旋钮），头部有快速出题的“来源对话”、“对抗清单”和“草稿：无”三行，泄漏自查做过，都在 `main` 上。
- 没有写 `drafts/`，没有跑探针，没有占用本机算力。
- queue.md 已按 tb-research 第 6 步分档重排，board.md 已刷新。
