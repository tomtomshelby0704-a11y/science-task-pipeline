# tb-harden：复审改难

## 触发口令

- `复审改难`：由出题侧 Claude（云端或本地，手动会话或定时任务）读 [runs/](../../flows/tb-science/runs/README.md) 里的校准记录与轨迹摘要，给每道已跑题打分；把**在修范围**内的题（强模型已跑、未达标的，定义见第 2 步）**每轮全部**依据其轨迹修成**新题**写进题库并排到队列顶部。2026-10-29 起条件 B 取消，弱模型结果不再决定修不修。原题不重跑。**可以同时开多个对话**：打分与每道原题的改难都先用 [claims/](../../flows/tb-science/claims/README.md) 占用，各对话自动错开。

## 目的

把跑过、强模型已跑但不达标的题变成下一道落在目标难度带内的题。GPT 5.6 很快做完（通过 3/4、4/4 或成功轨迹 < 50 步；50–59 步算近达标，不改难）的题，改难的目的是**拉长 GPT 5.6 的成功轨迹并让它做错**：让它必须反复回到数据和材料里诊断、核对、澄清才能做对。判断只依据要求书 [校准结果要求](../../specs/tb-science-requirements.md#校准结果要求合并验收标准-11--交付要求-21)（条件 A、C；条件 B 已于 2026-10-29 取消）与 [成功轨迹深度](../../specs/tb-science-requirements.md#成功轨迹深度合并验收标准-11--交付要求-22)；改难 / 加深 / 降难的方向只取要求书 [1.2 设计：难度来源与题面](../../specs/tb-science-requirements.md#12-设计难度来源与题面) 已列出的难度来源，具体手法见 [对抗出题规范](../../flows/tb-science/adversarial-design.md) C 节。本 Skill 还承担规范 F 节**对手档案**的维护：每打一行分就追加一行"这道题用了什么手法、GPT 实际怎么做的、手法有效与否"，这是出题侧对 GPT 5.6 能力边界的实测记录，`研究出题` / `快速出题` 据此选手法。只读仓库里的摘要，不需要执行机本地文件。

## 输出

- `flows/tb-science/runs/scores.md`：每道新出现校准记录的题追加一行。
- `flows/tb-science/adversarial-design.md` F 节对手档案：与 scores.md 每行对应追加一行（同一 commit）。
- `flows/tb-science/topics/<新题号>.md`：一个候选；头部 `来源对话：改难自 <原题号> 候选 <N>（runs/<原题号>/），<日期>`、`状态：待执行`、`起始候选：1`、`改难代数`、`对抗清单`。在修范围内每道原题各出 1 道，一轮出完。
- `flows/tb-science/claims/harden-score.md`、`claims/harden-<原题号>.md`：做的过程中存在，做完删除。
- `flows/tb-science/topics/queue.md`：新题置顶，其余保持原顺序。
- `flows/tb-science/board.md`：刷新。
- 全部推到 `main`。

## 步骤

占用、撞上、心跳、过期接手、释放的做法一律按 [claims/README](../../flows/tb-science/claims/README.md)，下文只说占什么。

**开局**：同 [tb-research 开局](../tb-research/SKILL.md#步骤)：`ds_prescreen.py --check` 有 key → 第 5 步默认做题面泄漏探针，并在对人类的第一句话说 `本轮出题使用本机 DeepSeek key（deepseek-flash）做出题阶段探针`；没有 key 不提。

**算力与时间**：同 tb-research，全程按 [AGENTS.md 出题侧算力与时间预算](../../AGENTS.md#出题侧算力与时间预算) 执行：每个计算进程单线程、带 `timeout 600`，同时至多 2 个；单题 ≤ 90 分钟，单轮 ≤ 3 小时。

1. `git pull --rebase origin main`；列出 `runs/*/calibration.md`。
2. **打分**：先数有校准记录、但题号+候选尚未出现在 scores.md 的题；另加最新一行距目标判断为 `待补测强模型`、且台账 1 有比它更晚的登记行的题（补测已完成，要重新打分）。没有 → 去第 3 步。有 → 占 `claims/harden-score.md`；占不到（别的对话正在打分）→ 不打分，直接去第 3 步。占到后，`git pull --rebase origin main` 重数一遍，对每道仍未打分的题读 calibration.md 的三项条件判定与结论、各次摘要的第 1、3 节，追加一行：题号、候选、结果、5.6 通过数/4、弱模型结论（填 `不跑`）、最小成功步数（2026-10-29 起此列填**最长**成功步数，写成 `最长 N（共 k 条成功）`：判据只要求至少一条成功达到 50 / 60）、距目标判断、处置。原题有“难度落点”字段时，在距目标判断后括注预测是否命中（`预测命中` / `预测偏易` / `预测偏难`）；在修范围内的行再括注 `距离 D`：D = 超出 2/4 的通过次数 × 15 + max(0, 50 − 最长成功步数)，`太难`（0/4）记 `距离 —`。本轮打分后若同一类设计（同一难度来源或同一领域的同类依赖链）累计 2 次被判 `太简单` 或 `太难`，在 calibration-models.md 第 4 节追加一行观察。距目标判断七选一：`已达标`；`近达标（保护留存）`（A、C 满足，没有 ≥ 60 步的成功轨迹，最长成功 50–59 步；执行机已冻结、审查、登记，处置固定为 `不处理`）；`已达标（重判）`（calibration.md 结论为不达标，原因只是旧深度规则“每条 ≥ 100 步”，按现行要求书 A、C 已满足且至少一条成功轨迹 ≥ 60 步：把该题状态改为 `待执行（重判，<原执行机>）`，头部加 `- **重判**：<日期> 按现行深度规则 <运行号> <N> 步满足，A、C 已满足（runs/<题号>/calibration.md）；回原执行机补 rubric 与证据后登记`，并置顶 queue.md，理由“重判，原执行机补登记”）；`太简单`（5.6 通过 3/4 或 4/4）；`太浅`（A、C 满足但全部成功轨迹 < 50 步）；`太难`（5.6 0/4 且 GPT-6 Astra 失败）；`无效运行待重跑`（结论里说明失败属无效）。**处置在打分时就定**：在修范围内的留空（留空 = 待修），其余填 `不处理`。**在修范围** = 强模型已跑、判为 `太简单`（5.6 通过 3/4 或 4/4）、`太浅`、`太难` 的题；换句话说，强模型跑过但没落进难度带的都修。**同系上限**：原题头部 `改难代数` 为 2（它本身已是改难题的改难题）且仍判 `太简单` / `太浅` → 处置填 `不处理（同系改难 2 代未入带）`，并在 calibration-models.md 第 4 节追加一行，写这类设计为什么拉不长。范围外：`待补测强模型`（强模型还没跑，等补测登记后再打分）、同系改难 2 代未入带、`无效运行待重跑`、`已达标`、`已达标（重判）`、`近达标（保护留存）`。**每打一行分，同时在 [对抗出题规范 F 节](../../flows/tb-science/adversarial-design.md#f-对手档案只追加) 追加一行对手档案**：原题头部 `对抗清单` 写的手法（没有就写"无"并从题面判断陷阱是否被点名）、实测（通过数 / 最长成功步 / 从摘要第 2 节引用 GPT 在第几步做了什么：从哪读出陷阱、第几步交卷、有没有回查）、结论 `有效` / `无效` / `未分辨`。打分行、对手档案行、calibration-models 追加行与删除 `claims/harden-score.md` 同一 commit，push。
3. **选题**：`git pull --rebase origin main`；取处置为空的全部行（都在修范围内），按第 2 步括注的距离 D 由小到大排，`太难` 排最后（`近达标（保护留存）` 的行处置固定为 `不处理`，永不选入；旧行没有 D 的，按其通过数与最长成功步数现算）。例：tbs-023（3/4、最长 26，D = 15 + 24 = 39）先于 tbs-003（4/4、最长 38，D = 30 + 12 = 42）先于 tbs-018（4/4、最长 23，D = 30 + 27 = 57）。**逐行全部处理**：对每一行先占 `claims/harden-<原题号>.md`，占到就做第 4–5 步，做完释放再取下一行；已有未过期的占用文件，或 push 时撞上 → 跳过这一行（别的对话在修）。原题当前状态为 `执行中`、`待执行（重判…）`、`待执行（退回…）`，或题文件写明 `复审改难` 暂不领 → 也跳过，处置保持空，等下一轮（原题可能就此达标）。没有待修行 → 本轮不出新题，跳到第 6 步。
4. **修题**：读原题该候选和 `runs/<原题号>/` 全部摘要，先从成功轨迹摘要第 2 节记下三件事：GPT 在第几步、从公开材料哪一处读出了陷阱或捷径；第几步交卷；交卷前有没有回查。然后按判断类型定方向（手法编号见 [对抗出题规范 C 节](../../flows/tb-science/adversarial-design.md#c-六种对抗手法)）：
   - 5.6 通过 3/4 或 4/4 的 `太简单`，**原题简报第 7 小节有加难旋钮** → **拧旋钮 + 零点名修复**，目标 ≤ 30 分钟：按简报写的数值拧 1–2 个旋钮（不重新设计），同时把轨迹显示被读出的那条信息从公开材料里拿掉（手法 1）；首发解重跑必须 0 分，参考解 1 分；其余设计沿用原题。
   - 5.6 通过 3/4 或 4/4 的 `太简单`，**没有旋钮**（旧题）→ 全套对抗设计，同 [tb-research 第 5 步](../tb-research/SKILL.md#步骤)：必含手法 1，且必含手法 2（延迟暴露）或 3（证据分叉）之一；优先把轨迹里"被读出的陷阱"改成只能从数据诊断得出，再加一层只在自查后暴露的问题，或把一刀切的处理改成按单元分叉的判断。判分按手法 5 贴边、分解，不公开数字。
   - `太浅`（A、C 满足但全部成功轨迹 < 50 步，加深）：难度已在带内，**保住**让 GPT 5.6 失败的那几处判断不动、不加新陷阱。从成功轨迹找出成功者压缩或跳过的环节，加手法 3（把一次性处理拆成须逐单元判断的分叉）或手法 6（要求交付一份只有做了独立检验才写得出的产物并判分），使成功轨迹自然变长。不得拼接无关操作或强制增加命令（要求书 1.2）。
   - `太难`（降难）：从全部失败轨迹第 3 节找出所有运行都栽在哪一环；若是多处陷阱合取，去掉或减弱其中一处（如补足题面应明确的信息、减少同时出现的陷阱），保留其余科学判断；不放宽由科学依据推出的容差。

   四种都不改领域，不改科学素材来源；都不得靠拉长题面、重复强调、格式陷阱、堆交付件或数据量、限资源、冷门记忆或强制命令数拉长轨迹（要求书 3.2，规范 A 节）。在新题“原创贡献”字段写明：`改难自 <原题号> 候选 <N>：原轨迹 <运行号> 第 __ 步显示 __，本题改为 __（手法 __）`。一道题从开写起 ≤ 90 分钟、拧旋钮的 ≤ 30 分钟（[AGENTS.md 出题侧算力与时间预算](../../AGENTS.md#出题侧算力与时间预算)）：到点仍没跑通就停手，释放 `claims/harden-<原题号>.md`，scores 行处置留空，留给下一轮换修法再做；做题途中按 claims 规则推心跳。
5. 写 `topics/<新题号>.md`（12 个字段齐全，“难度落点”写明用了手法 <编号>、引用对手档案、修改后为什么落回难度带、加深题和加难题写明“原轨迹第 N 步从 X 直接读出了 Y，新题里 Y 只能经 Z 诊断 / 核对得出”以及成功轨迹预计 ≥ 60 步的理由；`## 构建简报` 七小节齐全，只改与改难点相关的小节，其余沿用原题简报，原题没有简报就新写；第 6 小节第一项是首发解，第 7 小节 ≥ 2 个旋钮（拧过的旋钮写新值并再给下一档）；`drafts/<新题号>/` 从原题草稿复制后改，并按 [tb-research 第 5 步](../tb-research/SKILL.md#步骤) 的实跑要求跑通：参考解 1 分、`first_shot.py` 0 分且过公开自检、3 种子贴边容差——首发解通过就再改，不改容差）。写题前做**泄漏自查**（必做，规范手法 1）：把新题的题面、README、样本表、文件名、表头与附带材料逐份过一遍，对“核心难点”里每个本该只能从数据诊断的陷阱，确认公开材料里没有直接点出它的词句或能直接读出的线索（tbs-023 就因题面与 README 写明“部分实验分两天制备”，GPT 5.6 仍 3/4、最长 26 步）；点出了就改材料，不改陷阱。有 key 时再跑**题面泄漏探针**（约 20 秒，只给 DS 题面、不给数据）：`python skills/tb-prescreen/scripts/ds_prescreen.py --topic <新题号> --mode idea --no-data --write-summary`；DS 不看数据就点出了某个这样的陷阱 → 题面泄漏，改材料后重探，这是门槛。DS 一次性探针只作排序参考（tb-research 第 6 步），不再据此改设计或拦题。新题头部加两行：`- **改难代数**：<原题的改难代数 + 1；原题没有此行按 0 计>` 和 `- **对抗清单**：v1，<日期>；手法 <编号>；首发解 0 分（实跑，种子 k，挂在 __）；零点名 <自查 / 自查 + 探针 n 轮未点出>；分叉 <m 处>；旋钮 <k 个>`。按 tb-topic 占号规则 push；成功后，在下一个 commit 里把 scores.md 该行处置改为 `已改难为 <新题号>`，同时删除 `claims/harden-<原题号>.md`。
6. 重排 queue.md：本轮新题都有 `对抗清单`，按 [tb-research 第 6 步的分档](../tb-research/SKILL.md#步骤) 放进对抗档前列（档内按第 3 步的处理顺序），其余保持原顺序；没有新题则不动。运行 `python3 skills/tb-board/scripts/build_board.py`，queue.md、board.md 同一 commit，push。
7. 回报三行：scores.md `blob` 链接；本轮新题 `blob` 链接（多道用顿号分隔，或 `本轮无待修题`）；board.md `blob` 链接。

## 边界

- 不改原题文件、状态与台账；原题不重跑。唯一例外是第 2 步的 `已达标（重判）`：只改状态、加一行 `重判`、置顶队列，不改其他内容。
- scores.md 只追加；唯一可改的是持有 `claims/harden-<原题号>.md` 的对话，在第 5 步把该行“处置”单元格从空改为 `已改难为 <新题号>`。
- 不修范围外的题（待补测强模型、同系改难 2 代未入带、无效运行待重跑、已达标、近达标）：只打分记录，处置填 `不处理`。
- 不读执行机本地文件；摘要里没有的信息不臆测，改难理由必须引用摘要中的步号。
- 每轮处理全部待修行，每道原题出 1 道新题；多个对话并行时，靠 claims 各修不同的原题。

## 完成判据

- 每道有校准记录的题在 scores.md 有且仅有一行（同一题号+候选不重复），对手档案有对应的一行。
- 每道新题头部有 `改难代数` 与 `对抗清单`，草稿里 `first_shot.py` 实跑 0 分。
- 本轮开始时处置为空的行，都已改为 `已改难为 <新题号>`，或由别的对话持有未过期占用。
- 每道新题“原创贡献”引用了原轨迹的运行号与步号；在 `main` 上并位于 queue.md 所在档前列。
- 本对话占过的 claims 文件都已删除。
- board.md 已刷新。
