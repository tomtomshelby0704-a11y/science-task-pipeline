# tb-research：研究出题

## 触发口令

- `研究出题`：由出题侧 Claude（云端或本地，手动会话或定时任务）跑**一轮**。一轮是一个目标，不是一次动作：至少推进 3 件（入库 1 道题或否决 1 份素材各算 1 件），并把 [materials/](../../flows/tb-science/materials/README.md) 里待加工的素材清零。先加工素材（逐候选判断能否成题，能则改写成题入库，不能则否决），素材清零仍不足 5 件才自主研究补足。最后重排 [执行队列](../../flows/tb-science/topics/queue.md)、刷新看板。入库不经人类。

## 目的

题库的主入口（另两个是 [快速出题](../tb-quick/SKILL.md) 与 tb-harden 的改难题）。[tb-topic](../tb-topic/SKILL.md) 把要求书第一阶段约束组装成提示词给 GPT Pro，回复只是素材；本 Skill 负责把素材加工成题，或在没有素材时用**同一份提示词**自己做研究并回答。不是每份素材都必须成题，但每份被碰过的素材都要有结论。目标是出"恰到好处"的题：预计满足要求书 [校准结果要求](../../specs/tb-science-requirements.md#校准结果要求合并验收标准-11--交付要求-21) 条件 A 与 C（GPT 5.6 Sol (max) with Codex 通过 1–2/4）且成功轨迹满足 [成功轨迹深度](../../specs/tb-science-requirements.md#成功轨迹深度合并验收标准-11--交付要求-22)。

2026-10-29 起本 Skill 是**对抗式**的：出题 agent 直接对着校准目标设计——让 GPT 5.6 做错、让它不得不多走——手法、底线、首发解、对抗清单、对手档案都在 [对抗出题规范](../../flows/tb-science/adversarial-design.md)。出题侧的时间花在对抗设计和一次首发解实跑上，不花在多种子、真值核对、来源检索这类交付严谨性上（执行机 tb-run 第 2–4 步本来就重做）。排序是弱功能，只看题面拍一次，不为排序做研究。

## 输出

- `flows/tb-science/drafts/<题号>/`：**可运行草稿**，worker 题包的起点。固定文件：`README.md`（怎么跑、跑了什么、种子、贴边容差推导、首发解挂在哪、旋钮试拧结果、未验证项、版本）、`instruction.md`（题面草稿）、`generate_data.py`（按种子生成数据与隐藏真值）、`reference_solution.py`、`first_shot.py`（首发解，规范 D 节）、`verify.py`（子检查与二元奖励）、`requirements.txt`（固定版本）。只放代码与小型 fixture，不放生成数据（由种子复现）；每题目录 ≤ 200 KB；云端缺的库用 `pip install` 装固定版本，装不上就用 numpy / 纯 Python 实现。
- `flows/tb-science/topics/<题号>.md`：每道一个候选，格式即 [topic.md 模板](../tb-topic/templates/topic.md)，含 `## 构建简报` 七小节；头部 `状态：待执行`、`起始候选：1`、`对抗清单`（规范 E 节格式）、`来源对话`：素材加工时写 `GPT Pro 素材 <素材号> 候选 <N>，Claude 加工，<日期>`，自主研究时写 `Claude 研究（<会话标识>），<日期>`。一轮可写多道。
- 旧题回补（第 1 步）：给队列里没有 `对抗清单` 的题加 `对抗清单：v1（回补）…` 行和 `drafts/<题号>/first_shot.py`，或把首发解通过的题改为 `退回出题（首发解通过，<会话标识>）`。
- `flows/tb-science/materials/<素材号>.md`：状态改为 `已加工（→ <题号>, <题号>…）` 或 `已否决（<原因一句>）`，头部加每个候选的一句裁决。
- `flows/tb-science/topics/queue.md`：全量重排。
- `flows/tb-science/board.md`：刷新。
- 全部推到 `main`。

## 步骤

记一个计数器"推进件数 K"，初值 0；记待执行题数 N。

**开局**：在仓库根运行 `python skills/tb-prescreen/scripts/ds_prescreen.py --check`。输出 `key: 有, docker: 有` → 本轮默认做第 5 步的出题阶段探针，并在对人类的**第一句话**说：`本轮出题使用本机 DeepSeek key（deepseek-flash）做出题阶段探针`；其他输出（含脚本不存在、云端没有 key）→ 不提，照旧做，不做探针。

**算力与时间**：全程按 [AGENTS.md 出题侧算力与时间预算](../../AGENTS.md#出题侧算力与时间预算) 执行，开局记下本轮开始时间。每个计算进程（含容器）单线程、带 `timeout 600`，同时至多 2 个；单题 ≤ **60** 分钟（比 AGENTS 的 90 分钟上限更紧：删掉的多种子与真值核对不该再花时间），单轮 ≤ 3 小时。可以慢，不能把机器吃光。

1. `git pull --rebase origin main`。数 `topics/*.md` 中状态为 `待执行` 的题得 N。**先回补旧题**（每轮 ≤ 3 道）：从 queue.md 顶部起取状态 `待执行`、头部没有 `对抗清单` 行、且有 `drafts/<题号>/` 的题（来源是 [快速出题](../tb-quick/SKILL.md) 的没有草稿，跳过；审查退回、重判、补测的题跳过），逐题只看公开材料（草稿里的 `instruction.md` 与生成出的数据，不看参考解与验证器源码）写首发解 `drafts/<题号>/first_shot.py`（规范 D 节：常规方法、一次写完、产出全部文件、过公开自检），用草稿验证器实跑一次：
   - 奖励 0 → 头部加 `- **对抗清单**：v1（回补），<日期>；手法 <按原设计如实填，可以是"无"或只有 1>；首发解 0 分（实跑，种子 k，挂在 __）；零点名 <自查结论>；分叉 <m 处>；旋钮 <0，回补不补旋钮>`，简报第 6 小节第一项补首发解；它升入对抗档。
   - 奖励 1 → 状态改 `退回出题（首发解通过，<会话标识>）`，头部加一行 `- **退回出题**：<日期> 首发解 <一句话> 奖励 1，过了 <子检查>；待按对抗出题规范重写`，出队；来源素材头部该候选记 `待重做（首发解通过）`。退回的题下一轮由本 Skill 或 `快速出题` 按第 5 步重写：原号、原文件、原地改（它没跑过模型，没有台账），重写后状态回 `待执行`、对抗清单 `v2`。
   - 一题一 commit push，每道 K +1。首发解写不出来（公开材料不足以写出完整解法）→ 这道题本身题面不合要求书 1.2，同样退回。
   写之前读 `topics/*.md` 全部执行记录里标 `简报偏离` / `简报缺口` 的条目，反复出现的缺口要在新简报里写到。回补完后：**N ≥ 50 → 跳到第 6 步**，本轮不出新题，停止原因"达上限 50"。（原"补草稿"条款 2026-10-29 删除：没有草稿的题由执行机按简报从零构建，草稿不再是入队条件。）
2. **加工素材**：取 `materials/*.md` 中状态 `待加工`（含 `待加工（复审）`）的素材，先占 `claims/research-<素材号>.md`（做法按 [claims/README](../../flows/tb-science/claims/README.md)）：已有未过期占用、素材头部有 2 小时内的 `加工中` 标记、或 push 撞上 → 换下一份。多个对话同时跑时，一个从编号最小取起、其余可从最大取起，减少撞车。都占不到或没有 → 去第 3 步。占到后加工期间每推一题同 commit 更新心跳；素材加工完（状态改 `已加工` / `已否决`）的 commit 里删除占用文件。对它的**每个候选**逐条判断：
   - 要求书第一阶段红线（1.1 真实原创、1.2 难度来源与题面、1.3 数据）逐条过；
   - 5.1 近亲：对照 `topics/*.md` 全部题、`runs/` 已跑题、其他素材，以及**同一素材里已判可成题的候选**（候选之间近亲只留一个）；
   - 难度落点：对照 [对抗出题规范](../../flows/tb-science/adversarial-design.md) B 节（对手画像）、C 节（手法）、F 节（对手档案），以及 calibration-models.md 第 2 节（难度带）、第 4 节（实证修正）和 scores.md 里已跑题的"距目标判断"，能否写出"本题用手法 <编号>，对手档案 #<编号> 说明这类手法实测 <有效 / 无效>；为什么预计 GPT 5.6 Sol (max) with Codex 四次里能成功但不超过两次、为什么至少一条成功轨迹能达到 ≥ 60 步、GPT 5.6 预计在依赖链哪一环失败"的具体理由。scores.md 已把同类设计判为 `太简单` 或 `太难` 的、对手档案已判 `无效` 的手法组合，不按原设计成题（可改设计后再判）。

   **否决纪律**：否决一个候选，只能引用要求书第一阶段红线原句（1.1 真实原创与来源、1.2 假难度、1.3 数据不可信或不能离线）或 5.1 近亲，裁决写"条款号 + 原句 + 本候选哪里不符"。素材只提供科学问题与方向，数据、工具、判分都可以换。下面这些**不是否决理由**，必须改设计后成题：
   - 工具离线可行性未核实（SUMO、PyDrake、OpenFOAM、matRad 之类）→ 换可离线的开源工具或自写实现；确实核实不了的写进简报第 7 小节留给 worker。
   - 简报第 2、3 小节暂时写不出 → 改数据生成方案、改判分设计，直到写得出并能实跑；改三次仍构造不出可信真值，才引 1.3 原句否决。
   - 预计偏易 / GPT 5.6 稳过 → 按 1.2 至少加一项难度来源（可识别性判断、单位与采样条件核对、独立验证环节、陷阱场景），再判难度落点。
   - 规模偏小 → 扩大合成规模。R2/R3 多轮结构 → 并入单题的难度层。
   素材头部已有"候选裁决"的（复审）：已成题的候选跳过；其余候选按本纪律重新判断，新裁决追加为一节"复审裁决（<日期>）"，不删旧裁决。

   每个可成题的候选各出**一道**题：先做第 5 步开头的**对抗设计**，再补齐并改写成 topic.md 格式（可以改设计；难度落点的结论写进"难度落点"字段，支撑它的设计写进"核心难点""科研依赖链""产出与判分思路"）。来源核实与 [快速出题](../tb-quick/SKILL.md#步骤) 相同：不做广泛检索，只有用到具体外部工具或数据集时才用 WebSearch / WebFetch 查一次来源、版本、许可，查不到就写进简报第 7 小节；相似性自查写明对照了本仓库哪些题和你所知的哪些公开评测。按第 5 步写题，K +1，N +1。全部候选不能成题 → 素材状态改 `已否决（<原因一句>）`，K +1。某个候选从开写起 90 分钟仍没跑通 → 停手，素材头部给它记 `暂缓（超时，<卡在哪一步>）`：不算否决、不算推进件数，素材状态保持 `待加工`（其余候选照常处理），本轮做完其余候选后释放该素材的占用，下一轮或别的会话换设计再做。无论哪种，素材头部写每个候选的裁决，与题文件同一 commit push。然后**回到本步取下一份素材**；N 达 50 则停止加工，停止原因"达上限 50"。
3. **自主研究**：只在素材清零、K < 3 且 N < 50 时做。按 tb-topic"启动选题"第 1–4 步在内存里生成提示词（候选数 N = 1；不写 `-prompt.md`，不占号），自己充当被提问方回答它：用 WebSearch / WebFetch 核实素材的来源、版本、许可、能否离线打包，以及与公开评测题、竞赛题、现成 Issue/PR 的相似性；每条核实结果写进对应字段。难度落点同第 2 步判断并写进"难度落点"字段；不得靠凑步骤、冷门记忆或任意格式要求制造难度（要求书 3.2 原文）。成一题 K +1、N +1，重复本步直到 K ≥ 3 或 N ≥ 50；**连续 2 次**因近亲或红线放弃则停止，停止原因"自主研究连续放弃"。
4. 近亲自查：每道题写入前对照 `topics/*.md` 全部题、`runs/` 已跑题和待加工素材，同数据源、同原型或同核心解法（5.1）→ 放弃这一道，不写。
5. 写题 = 对抗设计 + 草稿 + 题文件，草稿与题文件同一 commit。
   - **对抗设计**（写代码前，纸面上做完）：按 [对抗出题规范 C 节](../../flows/tb-science/adversarial-design.md#c-六种对抗手法) 选 ≥ 2 种手法——必含手法 1（零点名），且含手法 2（延迟暴露）或 3（证据分叉）之一；写下首发解算法（规范 D 节：GPT 5.6 看完题面第一反应会怎么写）、它应该挂在哪个量上；用了手法 2 的写分层表，用了手法 3 的写分叉决策表（各分支在数据里都要真实出现）；定 ≥ 2 个加难旋钮（规范 E 节，具体数值）。设计不出"首发解必挂的那一层"就换候选，不写。
   - **草稿实跑**（每条命令带单线程前缀 `OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 OMP_NUM_THREADS=1 NUMEXPR_NUM_THREADS=1` 和 `timeout 600`，串行或至多两两并行；单次运行超时先缩小规模或换算法），只做三件：(a) `generate_data.py` → `reference_solution.py` → `verify.py` 奖励 1；(b) `first_shot.py` 奖励 **0**，且它产出了全部文件、过了公开自检——README 记它挂在哪个子检查、哪个量差多少；首发解拿到 1 分就改设计重跑（不是改容差），改两轮仍过则不成题；(c) 参考解换 3 个种子，按规范手法 5 定贴边容差（参考解离散度 1.5–2 倍与"首发解仍挂"的最大值取小）写进 README 与简报第 3 小节；每个旋钮至少拧一档跑一次首发解或参考解，确认方向写进简报第 7 小节。简报第 6 小节其余"合理简化"只写不跑，留给执行机实跑。**不再做**：≥ 5 种子分布、T1–T5 独立真值核对（只保留生成器自洽一项，其余由执行机 tb-run 第 2–4 步做）、思路探针。
   - **泄漏自查**（必做，规范手法 1）：逐份过题面、README、协议、样本表、文件名、表头与数据内文字，对"核心难点"里每个陷阱确认没有点出它的词句或能直接读出的线索；点出了就改材料，不改陷阱。有 key 时（开局 `--check`）再跑**题面泄漏探针**：`python skills/tb-prescreen/scripts/ds_prescreen.py --topic <题号> --mode idea --no-data --write-summary`（约 20 秒），DS 不看数据就点出某个本该只能从数据诊断的陷阱 → 改材料重探，这是门槛。然后可跑**一次性探针**（`--mode oneshot`，约 1.5–3 分钟，默认关闭思考）：结果**只作排序参考**，不改设计、不拦题；解出写 `- **预筛**：解出（一次性第 k 次解出；drafts/<题号>/prescreen.md）`，未解出写 `- **预筛**：通过（一次性 3 次未解出，未过子检查 …；drafts/<题号>/prescreen.md）`，`prescreen.md` 与题文件同一 commit。没有 key 跳过两个探针，泄漏自查照做。
   - 写 `topics/<题号>.md`：12 个字段齐全（"难度落点"写明手法编号与对手档案引用），头部 `对抗清单` 行按规范 E 节格式填（首发解写 `0 分（实跑，种子 k，挂在 __）`），`## 构建简报` 七小节齐全（第 6 小节第一项是首发解，第 7 小节含旋钮），头部"草稿"行指向 `drafts/<题号>/`，状态直接 `待执行`，`起始候选：1`，来源对话按"输出"节写。按 tb-topic 的占号规则 commit、push；push 被拒重算题号。
6. **排序**：列出全部 `待执行` 题（含本轮写的），只读题面。先分**两大档**：头部有 `对抗清单` 行的**对抗档**在前，没有的**旧档**在后——这是用户 2026-10-29 的决定：按对抗流程产出的题默认排在其他题之上。对抗档内：改难题与研究出题的题在前、快速出题的题在后；再按 `预筛` 通过 > 未预筛 > 解出。旧档内沿用原四档：`预筛` 为 `通过` 的研究出题与改难题；未预筛（含 `无效`）的研究出题与改难题；快速出题的题；`预筛` 为 `解出` 的。每档内按"预计最接近 GPT 5.6 通过 1–2/4、且至少一条成功轨迹 ≥ 60 步"排序（依据各题"难度落点"字段，参照 scores.md 与对手档案）。每题一句理由，对抗题在理由前标 `对抗 v1（手法 …）`，有预筛的在理由后加"预筛 <结论>"；重写 queue.md 全表（起始候选取各题头部字段）。审查退回、重判、补测的题仍置顶，不参与分档；`退回出题` 的题不在表内。不做研究，不改任何题。
7. 运行 `python3 skills/tb-board/scripts/build_board.py`，把 queue.md 与 board.md 放同一 commit，push。
8. 回报四行：第一行 `本轮推进 K 件：成题 <题号列表>；否决 <素材号：原因，…>；停止原因 <素材清零且 K ≥ 3 / 达上限 50 / 自主研究连续放弃 / 时间预算到>`，附各新题 `blob` 链接；第二行 `对抗：成题 <题号>（手法 …，首发解挂在 __）…；回补升档 <题号>…；退回出题 <题号>（首发解通过）…`；第三行 queue.md `blob` 链接；第四行 board.md `blob` 链接；有 key 时加第五行 `预筛：<题号> 通过 / 解出 …；泄漏探针改材料 <题号> k 轮`。链接按 AGENTS.md"回报链接"规则。

## 完成判据

- K ≥ 3 且待加工素材为 0，或回报里写明了其他停止原因之一（达上限 50 / 自主研究连续放弃 / 时间预算到）。
