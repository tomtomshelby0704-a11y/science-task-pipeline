# drafts/：可运行草稿

每道待执行题一个目录 `drafts/<题号>/`，由 `研究出题`（或 `复审改难`）写并在云端实跑通过，是执行机构建题包的**起点**。固定文件：

| 文件 | 内容 |
| --- | --- |
| `README.md` | 怎么跑、跑了什么、种子、容差推导结果、未验证项、版本记录 |
| `instruction.md` | 题面草稿（Agent 看到的任务说明） |
| `generate_data.py` | 按种子生成公开数据与隐藏真值（真值写到独立目录） |
| `reference_solution.py` | 参考解 |
| `verify.py` | 子检查与二元奖励，退出码或输出中给出 reward |
| `requirements.txt` | 固定版本 |

规则：

- 只放代码与小型 fixture，**不放生成数据**（由种子复现）；每题目录 ≤ 200 KB；不含密钥。
- 代码文件允许整体替换（台账类里的例外），替换时在 README 记版本与原因。
- **泄漏红线**：这里有参考解与真值。执行机构建镜像时只从 `package/<task_id>/environment/` 取构建上下文，`drafts/`、整个 repo 和 `.env` 不得进入 Agent 镜像或容器（tb-run 第 2 步）。
- 执行机以草稿为默认方案，实跑发现问题可偏离，按 tb-run 记 `简报偏离`。
