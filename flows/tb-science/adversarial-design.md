# 对抗出题规范

> 读者：[研究出题](../../skills/tb-research/SKILL.md)、[快速出题](../../skills/tb-quick/SKILL.md)、[复审改难](../../skills/tb-harden/SKILL.md) 三条出题链路，以及执行机 [tb-run](../../skills/tb-run/SKILL.md) 第 3 步的首发解闸门。A–E 节是规则，F 节"对手档案"只追加（`复审改难` 每打一行分就追加一行；出题时的"难度落点"必须引用它）。2026-10-29 起生效。

## A. 目标与底线

出题的目标就是校准结果本身：**GPT 5.6 Sol (max) with Codex 四次成功 1–2 次，且至少一条成功轨迹 ≥ 60 个 agent 步**（50–59 步算近达标）。出题 agent 直接对着这个目标设计，把时间花在"怎样让它做错、怎样让它不得不多走"上，而不是花在交付严谨性上——参考解多种子、工程检查、独立真值核对，执行机 tb-run 第 2–4 步本来就要重做一遍。

底线是要求书，一条都不放松：

- [1.2 难度来自科学判断](../../specs/tb-science-requirements.md#12-设计难度来源与题面)：题面必须明确科学目标、输入与约定、产出与格式、正确性要求与容差表述、允许的工具与资源；可以隐藏测试实例，**不能隐藏影响正确性的规则**；简单方法满足全部公开要求就要接受，不得临时加限制。
- [2.2 验证器与评分](../../specs/tb-science-requirements.md#22-验证器与评分)：容差事先声明、依据算法误差 / 数据精度 / 重复测量确定，**不能为拒绝某个答案事后收紧**；接受合理替代解。
- [3.2 假难度排除](../../specs/tb-science-requirements.md#32-模型校准与运行记录)：依赖缺失、断网缺资料、冷门记忆、机械重复、任意格式要求都不是难度；不人为拉长轨迹。

明令禁止的"对抗"：题意模糊或自相矛盾、格式陷阱、冷门记忆、堆数据量或交付件、限资源、事后收紧容差、把判分规则藏起来。这些做出来的失败是要求书 3.2 的**无效失败**，不能作校准证据，等于白跑。

## B. 对手画像：GPT 5.6 Sol (max) + Codex

以下每条都有本库轨迹为证（运行号 + 步号见 [runs/](runs/README.md) 摘要）：

| 特征 | 证据 | 对出题的含义 |
| --- | --- | --- |
| **每个 agent 步是一整段脚本。** 一步里读数据、分层、拟合、写文件全做完；25 步 = 25 段完整流水线 | tbs-024 1-gpt56-1：第 8 步已分好层并建好评估器，第 20 步已定标定，第 30 步交卷；tbs-025 1-gpt56-1：20 步交卷 | 只要"看完题面就能写出一份脚本"，步数封顶在 20–40。拉长步数的唯一办法是让这份脚本**写不出来或写出来必错**，模型不得不回到数据里多走几轮 |
| **从公开材料读陷阱，照单一次写完。** 题面、README、样本表、文件名、表头里点到的每个问题它都会处理 | tbs-001 三条成功轨迹都在第 8 步从样本表看出 S3 完全混杂；tbs-023 四次运行第 6–11 步直接去算题面点名的 ERCC GC 斜率；tbs-024 四次第 3–6 步按题面"every periodic image"写出像求和 | 陷阱的**存在**一旦被点名，就不再是陷阱。见手法 1 |
| **常规方法全会。** 稳健拟合、离群剔除、KM / Aalen–Johansen、谱分解、AR 修正、Fisher 边界都不用查 | tbs-024 第 10 步一眼看出 50σ 离群并改稳健拟合；tbs-025 第 8 步自己找出桥接通道与时间相关并做创新滤波 | 难度不能落在"知不知道方法"，要落在"知不知道这里该用、用在哪一段、参数从哪来" |
| **极少回读最终结果；自查只做内部一致性。** 没有外部真值时第一遍过了就交 | tbs-020 1-gpt56-2 第 67 步自查内部一致后宣告完成，C3 P90 15 > 14 min、C4 A 组 0.031 > 0.03 挂掉；外部证据：Toloka 测评约九成最终写入不回读 | 第一遍合理做法必须能产出**看起来对**的全套文件；真正的错只在判分时露馅。见手法 2、5 |
| **会做诊断，但只诊断显眼的。** 50σ、网格顺序、重复结构一眼看穿；10σ、打乱顺序、与噪声同量级的结构不主动找 | tbs-024 离群比噪声高 50–100 倍、按网格排列，四次都当场剔除；tbs-053 改为 10σ、20%、顺序打乱后 DS 一次性探针与常规稳健拟合都剔不掉 | 隐藏因素的信号强度要落在"做了针对性检验才看得见"的区间，不能肉眼可见，也不能淹没在噪声里 |
| **轨迹能变长的时候，是事件集合须反复探索、自查后返工。** | tbs-020 1-gpt56-1：第 7–27 步才把事件集合探索稳定（519 个事件、79 个漏记、51 条空记录），第 34 步起查边界事件，第 48 步自查发现日内残差漂移、重做基线 → 61 步 | 很多单元各需一次判断 + 一层只在自查后暴露的问题 = 自然的长轨迹。见手法 2、3 |

## C. 六种对抗手法

每道题至少用 **两种**：必含手法 1，且含手法 2 或 3 之一。手法编号写进题头部 `对抗清单` 和"难度落点"字段。

### 手法 1：零点名

- **定义**：公开材料（题面、README、协议、样本表、文件名、表头、注释、数据文件里的文字）不出现陷阱的存在、处理方法、"注意 / 可能 / 部分"之类的提示句，也不出现只有知道陷阱才会写的词（如"批次""漂移""离群""周期像"）。题面只写科学目标、输入约定、产出、容差表述与资源。
- **为什么有效**：对手画像第 2 条。tbs-001 → tbs-023 的改难失败就是题面写了"部分实验分两天制备"。
- **写法要求**：写完题做**泄漏自查**——逐份过公开材料，对"核心难点"里每个陷阱确认没有直接点出它的词句或能直接读出的线索；点出了就改材料，不改陷阱。有 key 时再跑题面泄漏探针 `python skills/tb-prescreen/scripts/ds_prescreen.py --topic <题号> --mode idea --no-data --write-summary`（约 20 秒，只给题面不给数据）：DS 不看数据就点出了某个本该只能从数据诊断的陷阱 → 泄漏，改材料后重探，这是门槛。
- **边界**：零点名不等于隐藏规则。协议定义、单位、坐标约定、容差的存在、判分检查哪些量，都必须写明（要求书 1.2）；藏的只是"数据里有什么问题"。

### 手法 2：延迟暴露

- **定义**：至少两层。第一遍合理做法产出的全部文件**通过题面能做的一切自检**（文件齐全、数值有限、守恒式闭合、拟合优度好看），只有做了某项**非显然**的核对——残差结构、第二来源交叉、留出集回代、分组分阶段对照——才暴露下一层问题；修完一层才看得到下一层。每一层对应判分里一个会挂的量。
- **为什么有效**：对手画像第 4、6 条。tbs-020 的日内漂移只在第 48 步的残差诊断后出现，发现它的那条轨迹 61 步成功，没发现的两条贴边失败。
- **写法要求**：简报第 6 小节写清每一层"第一遍做法 → 看起来对的证据 → 哪项核对暴露它 → 判分哪个量挂"。第一层必须是**首发解**（D 节）会走的那条路。
- **边界**：暴露路径必须是科研里本来就该做的核对（要求书 1.2 的"独立检查"），不是猜谜；不得靠随机注入与科学机制无关的错误。

### 手法 3：证据分叉

- **定义**：≥ 3 处决策依赖中间结果，且在不同单元 / 数据集 / 时段上走向**不同**——哪种机制适用、哪一段要剔、模型阶数是几、哪个近似在这一组不成立。写代码之前定不下来，必须先算、看、再定。
- **为什么有效**：对手画像第 1 条。分叉把"开写前就定好的单份脚本"变成必错，Codex 只能分轮探索，步数自然打开；tbs-020 的事件检出就是每个受试者、每个事件各判一次。
- **写法要求**：简报里列**分叉决策表**：决策 / 依据的中间证据 / 各分支在数据里各占多少 / 走错的后果落在判分哪个量。各分支在数据里都要真实出现，不能只在题面里存在。
- **边界**：分叉由科学机制决定（不同样本确实处于不同状态），不是人为把同一件事拆成多道工序；每处分叉删掉就会让任务以同样可靠性完成的，不算分叉。

### 手法 4：相互补偿

- **定义**：两种效应在朴素拟合里相互抵消或吸收（基线漂移被事件幅值吸收、阻力系数与自旋衰减互相补偿、增益与偏置共线），整体拟合优度好看；判分落在**分解量**、留出预测或外推量上，补偿的解在那里失效。
- **为什么有效**：模型看拟合优度判断对错（对手画像第 4 条）；补偿让第一遍必然"看起来对"。
- **写法要求**：判分不能只看总量或总拟合误差，要分别判分解出的分量、或判一段数据没参与拟合的预测。
- **边界**：分解量必须是科学上有意义、题面明确要求交付的量；不能靠"猜中参数真值"判分。

### 手法 5：贴边容差（合法）

- **定义**：容差在设计时定死，取两者之小：(a) 参考解 ≥ 3 个种子离散度的 1.5–2 倍；(b) 仍能让首发解和每个合理简化挂掉的最大值。写进简报第 3 小节并给出推导数字。之后执行机冻结时（≥ 7 种子）**只准放宽、不准收紧**。
- **为什么有效**：tbs-020 两次失败都是贴边（P90 15 > 14 min；0.031 > 0.03）；宽容差是 4/4 的主要来源之一。
- **写法要求**：判分量要**分解**（分组、分阶段、分构型各自判），不让一处偏差被另一处抵消；题面点名判分指标、不公开数字（官方 rubric #2、#16）。
- **边界**：(a) 是下限，低于参考解自身离散度就是拒绝正确解（要求书 2.2）；容差一旦公布 / 冻结，不得为了拒绝某个答案再收。

### 手法 6：独立验证产出

- **定义**：要求交付一份只有做了独立检验才写得出的产物——留出集预测值、守恒残差表、第二种方法的交叉值、无噪回代结果——验证器拿它对真值判分，不只看主结果。
- **为什么有效**：对手画像第 4 条；它跳过的正是这一步。要求书 1.2 把"最后用独立检查确认结果"列为合法环节，这一步在成功轨迹里自然多出 10–20 步。
- **写法要求**：验证产物有自己的子检查与容差；做了主结果却没做验证产物 → 奖励 0。
- **边界**：验证产物必须对科学结论有用（它本身能发现主结果的错），不是重复输出；不能退化成"再交一份格式"。

**规模靠决策数，不靠数据量。** 很多单元各需一次判断（tbs-020 519 个事件、24 个受试者各一条基线）可以拉长轨迹；单纯把数据加大、文件加多、交付件加多不行（要求书 3.2）。

## D. 首发解

**定义**：只看公开材料、用领域里最常规的方法、**一次写完**的完整解法——就是对手画像第 1 条那份脚本。它必须：

1. 产出题面要求的全部文件，格式正确；
2. 通过题面能做的一切自检（文件齐全、数值有限、守恒式闭合、拟合优度合理）；
3. 验证器奖励 **0**，且 README / 简报写明它在哪个子检查、哪个量上差多少。

首发解通过 = 这道题几乎必然 ≥ 3/4。它是对抗检验的核心，一次实跑约 10 分钟：

| 链路 | 做法 |
| --- | --- |
| 研究出题、复审改难 | 写 `drafts/<题号>/first_shot.py` **实跑**；奖励 1 就改设计重跑，改不动不成题 |
| 快速出题 | 不跑。简报第 6 小节第一项写首发解算法（≤ 10 行）+ "预计在第几层、哪个量上偏多少"；执行机按它实跑 |
| 执行机 tb-run 第 3 步 | 首发解先于其他反例实跑；奖励 1 → **不跑任何模型**，题状态改 `退回出题（首发解通过，<机器名>）`，省下四次 GPT 5.6 |

首发解不是稻草人：不许把它写成漏文件、单位错、明显胡来的版本。写首发解的人要问自己"GPT 5.6 看完题面第一反应会怎么写"，照那样写。

## E. 对抗清单与加难旋钮

**对抗清单**：题头部一行，三条链路写题时都写，格式固定：

```
- **对抗清单**：v1，<日期>；手法 <编号，如 1、2、5>；首发解 <0 分（实跑，种子 k，挂在 C3 0.047 > 0.03）/ 未实跑（执行机闸门）>；零点名 <自查 / 自查 + 探针 n 轮未点出>；分叉 <m 处>；旋钮 <k 个>
```

旧题回补时写 `v1（回补）`。有这一行的题在 [执行队列](topics/queue.md) 里排"对抗档"，在没有这一行的题之前（分档见 [tb-research 第 6 步](../../skills/tb-research/SKILL.md#步骤)）。

**加难旋钮**：简报第 7 小节列 ≥ 2 个，每个给**具体数值**与预期效果，例如：`老批次占比 20% → 30%，预计普通最小二乘 B 误差 0.35 → 0.5 meV`；`事件中位间隔 70 → 45 min，竞争占比 20% → 35%`；`起伏幅 2.0 → 2.6 Å，最大间隙分层混层构型 2 → 5 个`。研究出题 / 复审改难至少拧一档实跑确认方向；`复审改难` 对 `太简单` 的题优先拧旋钮，不重新设计。
