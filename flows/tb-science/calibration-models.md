## 2. 目标难度带（要求书 3.2 原文）

一句话：**GPT 5.6 Sol (max) with Codex 有时能做出来、但不是稳过（4 次成功 1–2 次），且至少一条成功轨迹要走 ≥ 60 个真实的 agent 步骤。** GPT 5.6 稳过的题不合格，GPT 5.6 和 GPT-6 都做不出的题也不合格。原文：

#### 校准结果要求〔合并：验收标准 §1.1 + 交付要求 §2.1〕


同一任务须在可比评测条件下同时满足以下三项条件，方可通过模型校准：

| 条件 | 所需证据 |
| --- | --- |
| 条件 A — 强模型组成功 | 至少一条来自符合条件的强模型组模型的完整成功轨迹，且成功结果经验证器确认。 |
| 条件 B — 弱模型组失败 | 至少一条来自符合条件的弱模型组模型的完整失败轨迹，且失败结果经验证器确认。 |
| 条件 C — 难度上限 | GPT 5.6 Sol (max) with Codex pass rate <= 2/4。如果 GPT 5.6 Sol (max) pass rate 为 0，则需要提交 GPT-6 Astra (with Codex) 成功轨迹一条。 |

三项条件均须满足。每组可任选一个符合条件的模型；条件 C 中的成功轨迹可同时作为条件 A 的证据。

> 2026-10-29 甲方进一步放宽：**不再要求条件 B**。校准不跑弱模型，通过模型校准只需条件 A 与条件 C 同时满足，再加成功轨迹深度。此前已跑的弱模型运行保留为历史，不入判定；弱模型成功也不再作为否决理由。

有效失败须体现模型在预先声明的执行预算内，未能满足定义清晰的任务要求。由基础设施中断、凭据无效、任务环境损坏、指令歧义或矛盾，以及指令与验证器不一致所导致的失败，不得作为任务难度的证据。

#### 成功轨迹深度〔合并：验收标准 §1.1 + 交付要求 §2.2〕


| 指标 | 要求 |
| --- | --- |
| 成功轨迹深度 | 每项任务**至少一条**成功轨迹包含 ≥ 60 个智能体步骤（agent turns） |
| 步骤计数 | 采用有明确文档说明且一致的智能体步骤定义 |

只要求至少一条成功轨迹满足；其余成功轨迹（含条件 A、条件 C 中 GPT 5.6 Sol (max) 的成功轨迹）不要求每条达到 60 步。失败轨迹不计入成功轨迹深度统计。不按 output tokens 分档，不设批次中位数目标。不得通过无意义操作、重复命令或刻意拆分响应凑步骤数。

> 2026-10-29 按甲方反馈修订。原要求为“每条符合条件的成功轨迹 ≥ 100 个智能体步骤；批次 P50 150 个”，已删除。

> 2026-10-29 甲方进一步放宽，流水线据此加**近达标档**：标准仍为“至少一条成功轨迹 ≥ 60 步”，这一档仍是第一目标。三项条件都满足、但最长成功轨迹只有 **50–59 步**的题，也算成功：冻结保护、打包、审查、登记，不再改难。它必须和 ≥ 60 的题分开：交付包名带 `-d50`，台账写 `近达标（50–59；…）`，状态为 `已执行-近达标`，看板单独计数。< 50 仍判不达标。

假难度排除（[3.2 难度有真实运行支撑](../../specs/tb-science-requirements.md#难度有真实运行支撑成功轨迹完整质量标准-8)）：

- 排除依赖缺失、断网导致必要资料不可得、冷门记忆、机械重复和任意格式要求造成的假难度，不人为拉长轨迹。

我们的读法（据此选题，一切以要求书原文为准）：

1. **区分度不在工程熟练度。** 它在通用终端、写代码、修 bug 上与 GPT-5.6 持平甚至更强，难点只是“环境复杂、步骤多、代码量大”的题拉不开差距。
2. **区分度在科学判断。** 它在科研工作流（TB-Science 0%）和前沿科学推理（HLE）上明显落后。难点应落在：识别数据或问题里的科学陷阱、选对方法或模型、对结果做独立的物理或统计一致性检查。这与要求书 1.2“难度来自科学判断”一致。
3. **它很少承认不确定，倾向给出看似合理的答案。** 适合设计“随手能跑出一个数，但只有做了科学自查才发现错”的题，并在判分里检查科学正确性，而不是只查格式。请把这种“看似合理的简化做法”写进“核心难点”，并在“难度落点”字段说明弱模型预计失败在哪一环。
4. 图像类科学数据（显微、遥感、谱图等）是它的弱项，可以作为难点之一，但必须是科学上必要的输入，不能变成格式障碍。
5. 不要靠冷门记忆、断网缺资料、任意格式要求或机械重复制造难度（要求书 3.2 明确把这些列为假难度）。
